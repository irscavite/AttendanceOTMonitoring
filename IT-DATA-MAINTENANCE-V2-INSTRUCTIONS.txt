IT DATA MAINTENANCE V2 - DATE INDEXED

WHAT CHANGED
- Department only (no All), manual Load.
- Firebase queries request only records for the chosen date and owner shard rather than downloading each owner's entire history.
- Single delete reads that exact record path, verifies chosen department and date, and removes it.
- Date delete queries selected date rows only.
- Linked leave-generated attendance checks date-specific records instead of full attendance history.

MANDATORY FIREBASE DATABASE INDEX DEPLOY
The included database.rules.json adds indexes at v2/collections/$collection/$employeeNo/items:
  date, otDate, dutyDate, startDate

From the project directory with Firebase CLI installed, logged into the CORRECT Firebase project:
  firebase use
  firebase deploy --only database

IMPORTANT: This deploy replaces the target project's database security rules with the included rules; compare with current production rules and make a backup before applying. Never replace newer production rules blindly.

If rules are not deployed, date queries may remain slow or return Firebase index errors.

LIMITATION
This system still queries one employee shard at a time, so for very large departments the number of network requests can remain substantial. A dedicated v3 by-department/by-date index populated by the write path and backfilled from historic data is needed for truly one-request, constant-size reads. This revision does not change write data format or migrate historical records.

PROTECTION
Back up Firebase RTDB before testing deletes. Test one disposable record first.
