BEFORE FIRST USE IN FIREBASE CONSOLE
1. Open Authentication > Sign-in method.
   Enable Email/Password.

2. Open Realtime Database > Rules.
   Paste the contents of database.rules.json and Publish.

3. Open/host the web app.
   If /system/bootstrapComplete is not true, the Initial System Setup panel appears.

4. Create the first IT and HR accounts from the setup panel.
   These accounts are created in Firebase Authentication and their role profiles are created in Realtime Database.

5. Sign in using the username you created.
   The app internally maps a username such as "mackie" to "mackie@otmonitoring.local" for Firebase Email/Password Authentication.

EMPLOYEE / ACCOUNT WORKFLOW
- There are no built-in/demo accounts or sample employees in this build.
- HR registers employees in Employee Master List.
- Every HR-created employee automatically creates an Account Creation Request for IT.
- IT creates the employee Firebase Authentication login.
- IT assigns access as Employee, Supervisor, Request Approver, HR, or IT.
- Passwords are handled by Firebase Authentication and are not stored in Realtime Database or localStorage.
- IT can disable an account or change its system access.
- Resetting another Firebase user's password requires Firebase Console or a trusted Admin SDK backend.

IMPORTANT ABOUT OLD FIREBASE AUTH USERS
This ZIP contains no built-in accounts. If the Firebase project already has users under Authentication > Users,
those cloud Authentication users are not deleted by the browser app. Remove unwanted old users from the Firebase
Console before first setup if you want Authentication itself to be completely empty.

IMPORTANT - EXISTING FIREBASE AUTH USERS
----------------------------------------
If you already created the IT and HR users manually in Firebase Console > Authentication > Users, DO NOT create different users.
1. Publish database.rules.json in Realtime Database > Rules.
2. Open the web app.
3. Under INITIAL SYSTEM SETUP, enter the exact same Firebase Authentication email/username and password for IT and HR.
4. Click Create / Link IT & HR Accounts.
5. The app will detect that the Authentication users already exist, sign in to each one, and create the required /accounts/<uid> role profiles in Realtime Database.
6. After linking, use the normal login form.

The app accepts a full Firebase email address. A short username such as "it" is internally mapped to "it@otmonitoring.local". If you manually created a different email in Firebase Authentication, enter the FULL EMAIL, not only "it" or "hr".

Also make sure Authentication > Sign-in method > Email/Password is ENABLED.
Run the app through localhost, GitHub Pages, or Firebase Hosting; do not rely on opening index.html directly with file://.
